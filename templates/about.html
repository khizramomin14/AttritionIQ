About AttritionIQ

IBM SkillsBuild · Data Analytics with AI Internship Project

Project Overview

AttritionIQ is an AI-powered HR analytics application built as part of the IBM SkillsBuild Data Analytics with AI virtual internship programme. It analyses employee attrition patterns, predicts flight-risk using machine learning, and generates practical HR retention recommendations — all from the publicly available IBM HR Analytics Employee Attrition & Performance dataset.

Dataset

The project uses the IBM HR Analytics Employee Attrition & Performance dataset, a fictional dataset created by IBM data scientists. It contains approximately 1,470 employee records with 35 attributes covering demographics, job information, satisfaction levels and compensation.

  • Source: IBM (fictional dataset)
  • Rows: ~1,470 employees
  • Columns: 35 features
  • Target: Attrition (Yes / No)

Machine Learning Pipeline

  • Preprocessing: StandardScaler (numeric), OneHotEncoder (categorical), ColumnTransformer pipeline.
  • Class imbalance: Handled using class_weight="balanced" across all models.
  • Models evaluated: Logistic Regression, Decision Tree, Random Forest, Gradient Boosting.
  • Model selection: Based on combined F1-score + Recall + ROC-AUC (equal weighting).
  • Explainability: Feature importance from tree-based models, weighted by input deviation.

⚖️ Ethical AI Statement

This project is built for educational and demonstration purposes only.

  • The IBM HR dataset is entirely fictional and does not represent real employees.
  • Predictions are decision-support tools only and must not be used to terminate, penalise, or automatically reject real employees.
  • The model does not use protected attributes (e.g., Gender, MaritalStatus) as the basis for recommendations.
  • Model predictions represent statistical patterns, not causal relationships.
  • HR professionals should review all predictions before taking any action.
  • Employee privacy must be protected in any real deployment.
  • Risk thresholds (Low/Medium/High) are configurable and are not official IBM HR thresholds.
  • This project demonstrates analytics and ML techniques — it is not an actual IBM HR decision system.

Limitations & Future Improvements

  • Dataset is fictional — predictions should not be applied to real HR contexts without domain validation.
  • Model was trained on a single snapshot; no time-series or longitudinal analysis.
  • Full SHAP explainability (Shapley values) could replace the current lightweight approximation.
  • Hyperparameter tuning (GridSearchCV / Optuna) could further improve model performance.
  • A real deployment would require authentication, audit logging and data governance controls.
  • Integration with live HRIS systems would enable real-time monitoring.
